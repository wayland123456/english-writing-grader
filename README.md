# 墨韵批文 · 英语 —— 高考英语应用文智能批改平台

**在线地址**：<https://wayland123456.github.io/english-writing-grader/>

武汉市江夏实验高级中学英语组用（学校名称显示在报告抬头与页脚），**零后端、纯静态页面**，与语文版「墨韵批文」同一套界面骨架。

- **本地规则引擎**：不填 Key 也能批改，逐条比对要点覆盖、句式档次、词汇丰富度、衔接词、低级错误，按五档细则出分
- **AI 语义评分**：填 Key 后由大模型逐句评阅，再把维度分交回同一套硬规则封顶、扣分，**不让 AI 心软打分**
- **手写拍照**：qwen-vl 多图整篇转录，拼写与语法错误原样保留（不替学生改）

## 五档细则怎么落到代码里

评分链路是「六维加权 → 综合分 → 查表定档 → 硬规则封顶 → 档内定分 → 扣分」六步，任何一步都能在报告里看到依据。

| 维度 | 权重 | 判什么 |
|---|---|---|
| 要点覆盖 | 34% | 题干要点是否逐条写到（关键词 + 语义双重判定） |
| 语法结构 | 21% | 定语从句、非谓语、倒装、强调句、名词性从句等高级句式的密度 |
| 词汇丰富 | 13% | 高级词替换、Guiraud 多样性指数、同义改写 |
| 连贯衔接 | 14% | 高级 / 中级 / 基础连接词的使用层次 |
| 语言准确 | 12% | 拼写、固定搭配、主谓一致、冠词、时态 |
| 格式规范 | 6% | 称呼、落款、标题（按体裁判断） |

**档位门槛**：综合分 ≥80 → 第五档，≥63 → 第四档，≥47 → 第三档，≥30 → 第二档，≥12 → 第一档，<12 → 0 分。

**硬规则（细则里"必须扣"的部分，一律前端兜底，AI 说了不算）**：

- 漏 1 个要点 → 最高第四档；漏 2 个 → 最高第三档；漏 3 个及以上 → 最高第二档
- 少于 60 词或多于 100 词 → 扣 2 分；不足 25 词 → 最高第二档；不足 15 词 → 记 0 分
- 书信 / 申请信无称呼又无落款 → 扣 2 分；缺一样 → 扣 1 分
- 低级错误（拼写 / 搭配 / 主谓一致）每 3 处降一档，最多降 2 档
- 衔接成分明显不足（<45）不能进第五档
- 0 分卷不再记扣分（避免"0 分又扣 2 分"的怪显示）

## 功能

- **两种录入方式**：手写拍照上传（自动压缩、按页序编号、多图整篇转录）／直接粘贴文字
- **试题上传**：题干可粘贴文字，也可上传截图，「识别试题」自动填入
- **要点可编辑**：内置 5 道题模板，也可自定义要点；每条要点填英文关键词，用于自动判定是否写到
- **批改报告七章**：总评 → 内容要点（命中 / 缺失 + 原文依据）→ 能力维度（雷达图 + 进度条）→ 档位与扣分（封顶理由逐条列出）→ 语言诊断（句式 / 词汇 / 衔接分层统计）→ 语言错误表 → 五档对照
- **原文标注**：蓝＝亮点句式，黄＝衔接词，红＝错误（悬停显示原因）
- **升格建议**：指出从当前档进下一档最省力的 1–3 处改动
- **导出**：一键 A4 PDF（带学校抬头，html2canvas + jsPDF，自动分页；轻微超高时等比缩到单页）、打印、复制纯文本评语
- **历史记录**：本地保存最近 100 篇，可按姓名 / 题干搜索，支持"查看报告"与"载入到批改页重改"

## 使用步骤

1. 打开 `index.html`（或部署后的网址）
2. 先点「载入示例作文」→「开始批改」，不填 Key 也能看到完整的本地规则批改效果
3. 进「设置」→ 选后端：
   - **通义千问**（推荐）：只填一个阿里云百炼 API Key（bailian.console.aliyun.com → API-KEY 管理 → 创建），批改与手写识别共用
   - **其他 OpenAI 兼容服务**：填 Base URL + 模型名 + Key（DeepSeek / Kimi / 智谱均可）；但如果要拍手写照片，仍需再填一份通义 Key 给 Qwen-VL
4. 点「测试连接」确认通路，再「保存设置」
5. 回「应用文批改」：填姓名（选填）→ 选题材与题目模板 → 录入作文 → 「开始批改」

## 两种后端怎么选

| 维度 | 通义千问（qwen-plus / qwen-max） | 其他 OpenAI 兼容（DeepSeek / Kimi / 智谱） |
|---|---|---|
| 配置难度 | ★☆☆ 一个 Key 全搞定 | ★★☆ 批改一个 Key，OCR 还要一个通义 Key |
| 英语批改质量 | ★★★★ | ★★★★☆ DeepSeek 语义判断略强 |
| 手写识别 | qwen-vl-ocr / qwen-vl-max | 无（必须借通义） |
| 成本 | 便宜，按 token 计 | DeepSeek 更便宜 |

**建议**：日常用通义，一个 Key 覆盖全部功能；只在需要更强语义评阅时换 DeepSeek，OCR 仍留通义。

## 部署

纯静态站点，任意静态托管均可：

- **GitHub Pages**：仓库 → Settings → Pages → Source 选 `main` 分支 `/ (root)` → 保存，稍等 1 分钟即可访问
- **校内网盘 / U 盘**：直接双击 `index.html`（推荐 Chrome / Edge）

### 遇到跨域拦截怎么办

浏览器直连 AI 接口偶尔会被 CORS 拦下。仓库内附 `proxy.js`（零依赖，Node 内置模块）：

```bash
node proxy.js          # 默认 8787 端口
```

设置页「接口地址」填 `http://localhost:8787/proxy/api.deepseek.com/v1` 即可（带域名白名单，不会变成开放代理）。

## 常见问题

**Q：没填 Key 能批改吗？**
能。走本地规则引擎，要点覆盖、词数、格式、句式密度、连接词、拼写搭配全部本地判定；只缺"语义是否真的扣题"这一层判断，分数会略保守。

**Q：分数偏高 / 偏低怎么办？**
五档是硬边界，档内定分靠综合分位置。若整班普遍偏一档，改 `js/rubric.js` 里的 `thresholds` 或 `weights` 即可，不用动逻辑。

**Q：API Key 安全吗？**
只存在本机浏览器 localStorage，不上传任何服务器。教师机录一次即可；换电脑或换浏览器要重填。

**Q：手写识别结果有错字怎么办？**
识别结果会填进「直接输入文字」框，改完再批改。提示词已明确要求"原样保留学生的拼写错误"，不会替学生改正——这是评分准确的前提。

**Q：能批读后续写吗？**
当前版本按应用文（15 分制）做。读后续写是 25 分制、另有情节 / 人设 / 情感升华维度，需要单独改评分表和维度权重。

## 目录结构

```
index.html            单页入口（顶栏 + 三个标签页）
css/style.css         宣纸底 + 靛蓝主色的界面与报告样式
js/rubric.js          评分细则数据层：五档、六维、权重、连接词、句式正则、高级词表、错误词表、5 道内置题
js/engine.js          本地评分引擎：analyze / grade / finalize / annotate
js/api.js             AI 接口层：批改提示词 + qwen-vl 多图 OCR + 连接测试
js/report.js          A4 报告生成：buildHtml / toPdf / printReport
js/app.js             主控：表单、上传压缩、批改流程、结果渲染、历史、设置
js/vendor/            html2canvas、jsPDF
proxy.js              可选：本地跨域代理（零依赖）
```
